Troubleshooting

Start here before asking for help. Most problems are one of a small number of things, and this page covers them in the order they come up.

First: turn the error messages on

By default the application hides PHP errors, which is correct for a live site but means a broken page shows nothing at all. To see what is actually wrong, add this line to includes/config.local.php:

define( '_DEBUG_MODE', true );

Reload the page. Instead of a blank screen you get the error, with the file and line number. That is nearly always enough to tell you what to fix, and it is the single most useful thing you can do before reporting a problem.

Turn it off again

Debug mode shows error messages to everyone, including anyone who finds your site. Those messages can include file paths and query fragments. Remove the line as soon as you have what you need.

The site will not load at all

A completely blank page

PHP hit a fatal error and the message is hidden. Turn on debug mode as above. If the page is still blank afterwards, PHP itself failed to start — look in your hosting control panel’s error log, which will have the reason.

“PHP version of 8.4 or above is REQUIRED”

Exactly what it says. Change the PHP version for your account in your hosting control panel. If you have several domains on one account, make sure you changed it for the right one.

“Connect failed” followed by a database message

The application cannot reach your database. In order of likelihood:

  • The details in includes/config.local.php are wrong. Check for a typo, a stray space inside the quotes, or a missing semicolon.
  • The file does not exist, so defaults are being used. This is what happens after an upgrade if you skipped the step that recreates it — see Upgrading from 2.x.
  • Your host uses a database server name other than localhost.
  • The database user does not have rights on that database.

The message after “Connect failed” comes from the database server itself and is worth reading: Access denied means wrong credentials, Unknown database means the name is wrong, and a connection timeout means the host is wrong.

The setup wizard appears on a site that was already working

The application connected to a database but could not find its tables, so it concluded it was not installed yet.

Do not click through the wizard

It would build a second, empty installation. Your data is almost certainly fine — the application is simply pointed at the wrong place.

Check the database name and the table prefix in includes/config.local.php against what is actually in your database. A wrong prefix is the usual cause: the tables are right there but the application is looking for differently named ones.

Every link gives a 404

The home page loads but clicking anything gives a “not found” from the web server rather than from the application.

The server is not sending requests to index.php. Either mod_rewrite is off, the .htaccess file did not upload, your server is ignoring .htaccess, or you are on nginx.

The quick fix that always works: add this to includes/config.local.php.

define( '_REWRITE_LINKS', false );

Links fall back to a form that needs no rewriting. They are less tidy but entirely functional. The better fix is to get rewriting working — see Configuration.

Login problems

SymptomCause and fix
The login form reloads with no message Sessions are not persisting. Check that temp/ exists and is writable by PHP.
Logged out after every click Same cause, or the site address in System Settings does not match the address you are actually using — for example it says http and you are on https, or it has www and you do not.
Correct password rejected Check caps lock, then confirm you are using the email address rather than a name. If you are locked out entirely, set a new password hash directly in the user table using phpMyAdmin.
Password reset email never arrives A mail problem, not a login problem. See below.
Logged in but the menu is nearly empty That account’s role has few permissions. Check Settings → User Roles as an administrator.

Email is not being sent

Work through these in order.

  1. Send a test message

    From Settings → Email. If the test arrives and real notifications do not, your mail settings are fine and the problem is the template or the trigger — skip to the last step.

  2. Check the spam folder

    Mail sent by a web server from a domain it is not authorised to send for is very often filed as spam. This is the most common cause by far.

  3. Switch to SMTP

    If you are using the server’s own mail function, many hosts block or silently drop it. Tick Use SMTP and enter credentials for a real mailbox or a transactional email provider. Deliverability improves immediately because the mail is then being sent by a server allowed to send as your domain.

  4. Check the encryption setting

    TLS on port 587 suits most providers. SSL on port 465 is the older alternative. If you see a connection error, this and the port are almost always the cause. Sending over SSL or TLS needs the openssl PHP extension.

  5. Check the sending limit

    If mail stops partway through a large send, the rate limit on the same settings screen may be lower than your provider allows, or your provider is rejecting the rate. Adjust it to match.

  6. Check the scheduled task

    Some mail is queued rather than sent immediately. If the scheduled task is not running, that mail waits forever. See Scheduled tasks.

PDFs

SymptomCause and fix
The PDF is empty or will not openUsually a permissions problem on temp/, where the file is built. Make sure it is writable.
Images are missing from the PDFImage addresses in your template must be reachable by the server itself. A relative path that works in a browser may not resolve when the PDF is generated. Use a full address.
The layout is wrongThe PDF engine supports a useful but limited subset of CSS. Modern layout features do not work; tables do. If you have customised the template, simplify the layout.
Non-Latin characters show as boxesThe default fonts do not cover every script. This needs a font that does, added to the PDF engine.

Uploads

SymptomCause and fix
Upload fails with no messageThe target folder is not writable. See the list in Requirements.
Large files fail, small ones workPHP’s own limits. Raise upload_max_filesize and post_max_size, which most control panels expose.
Uploads work but downloads give “not found”The files are there but not being served. Check you have not moved file storage without setting the matching web address — see Configuration.

Appearance

SymptomCause and fix
The page loads with no styling at allThe combined stylesheet is not being served. Check temp/ is writable, and that your server is not denying .css and .js files inside it.
A style change does not showReload bypassing the cache (Ctrl/Cmd + Shift + R). If that does not work, delete the files in temp/.
Mixed content warnings on HTTPSThe site address in System Settings still says http. Change it to https.

Things that quietly never happen

These have no error message, because nothing failed — the work simply never started.

SymptomCause
Recurring invoices never go outThe scheduled task is not running. See Scheduled tasks.
Subscriptions never renewSame.
Ticket replies are not collected from the mailboxSame, or the imap PHP extension is missing.
A customer paid but the invoice is still unpaidThe gateway’s webhook is not reaching your site. See Payment methods.
Backups never appearThe zip PHP extension is missing, or the backup folder is not writable.

After an update

SymptomCause and fix
“Unknown column” or “table does not exist”The database upgrade has not been run. Go to Settings → Upgrade and click Run Manual Upgrades.
Your customisations have vanishedThey were edits to shipped files, which the update replaced. Restore them from your backup and move them into custom/ this time — see Customising.
One screen errors, the rest are fineUsually a customised file that PHP 8.4 is stricter about. Turn on debug mode to see the exact line.
Emailed payment links no longer workThe installation secret changed. See Upgrading from 2.x. Re-send the affected invoices.

Getting help

If none of the above resolves it, ask through the item’s comments page on CodeCanyon. Include these four things and you will usually get a usable answer first time:

  1. The exact error message, with debug mode on.
  2. Your PHP version and whether the server is Apache or nginx.
  3. What you did immediately before it happened.
  4. Whether this is a new installation or an upgrade, and from which version.
Never post credentials

Do not include database passwords, payment gateway keys, the contents of config.local.php, or the address of your scheduled task — that last one contains a password even though it does not look like one. Replace anything sensitive with … before posting.
